# UIデザイン仕様書

## 1. 対象

- アプリ名：たかがAI、されどAI。
- 対象URL：`http://127.0.0.1:5173/`
- 対象端末：スマートフォン縦画面
- 最小対応幅：320px
- PC表示：スマートフォン幅のアプリを中央配置
- 外部画像・外部フォント：不使用

## 2. デザインコンセプト

人類とAIの対決を、テレビのバラエティ番組とモバイルゲームの中間として表現する。

- 人類：黄色、暖色、手触りのある押し込み表現
- AI：シアン、寒色、情報表示・HUD表現
- 共通：濃い黒、生成りの紙色、太い境界線
- 重要操作：大きなボタンと明確な押下状態
- 画面遷移：1画面につき1つの主要行動に絞る

## 3. カラートークン

`src/styles.css`の`:root`で定義する。

| トークン | 値 | 用途 |
|---|---|---|
| `--ink` | `#17191f` | 基本文字、境界線、暗い背景 |
| `--muted` | `#686d78` | 補足文、非主要情報 |
| `--paper` | `#f5f1e8` | アプリの基本背景 |
| `--panel` | `#fffdf8` | カード、入力面 |
| `--line` | `#d8d3c9` | 通常の境界線 |
| `--human` | `#f4d13f` | 人類、主要ボタン、進捗 |
| `--human-deep` | `#8d6f00` | 黄色面上の補助文字 |
| `--ai` | `#46d6e7` | AI、情報表示、AI回答 |
| `--ai-deep` | `#08798b` | シアン面上の補助文字 |
| `--danger` | `#ff5d55` | 時間警告、挽回チャレンジ |

背景には黒を基調とした放射グラデーションを使用し、装飾画像なしで人類色とAI色を示す。

## 4. タイポグラフィ

```css
font-family:
  Inter,
  "Hiragino Kaku Gothic ProN",
  "Yu Gothic",
  Meiryo,
  system-ui,
  sans-serif;
```

- 基本文：端末の日本語ゴシック体
- タイトル：`font-weight: 950`相当の極太表示
- ボタン：太字、字間`0.03em`
- 英字ラベル：大文字、広めの字間
- 数字：`font-variant-numeric: tabular-nums`
- 本文の最小サイズ：9pxは補助ラベルのみに限定

## 5. 全体レイアウト

### アプリ外枠

- 最大幅：460px
- 最小高さ：100vh
- スマートフォン：画面幅いっぱい
- 620px以上：上下24pxの余白、角丸28px
- 横方向のはみ出しは禁止

### ヘッダー

- 高さ：最低66px
- 背景：`#11131a`
- 左：人類／AIのブランドマーク
- 中央：アプリ名、`LOCAL PROTOTYPE`
- 右：トップへ戻るボタン

### ゲーム情報

- 高さ：最低72px
- 左：現在フェーズ、ラウンド番号またはルームコード
- 右：人類とAIの得点

### コンテンツ

- 横余白：18px
- 上余白：20px
- 下余白：30pxまたはセーフエリア
- 主要要素間：16px

## 6. 主要コンポーネント

### ボタン

- 最小高さ：54px
- 角丸：15px
- 境界線：2px
- 主要ボタン：人類色、黒文字、下方向に5pxの影
- 副ボタン：パネル色、黒文字
- 危険・挽回操作：赤背景、白文字
- 押下時：2px下へ移動し、影を消す
- 無効時：不透明度38%、操作不可

### パネル

- 背景：`--panel`
- 境界線：1px `--line`
- 角丸：18px
- 内側余白：17px
- 下方向に5pxの弱い影

### 回答カード

- 通常：白背景、黒い2px境界線
- 人類公開後：黄色系背景
- AI公開後：シアン系背景
- 回答A・Bは29pxのラベルで識別
- 投票数と正体は右上に表示

### タイマー

- バーと秒数を横並びにする
- 通常：人類色
- 残り25%以下：危険色
- 残り時間は`deadlineAt - Date.now()`から算出

### 得点表示

- 人類とAIを左右に配置
- 人類ラベル：黄色
- AIラベル：シアン
- 得点数字：28px以上、等幅数字

## 7. トップページ

### 構成

1. 英字のゲームジャンル表示
2. 「たかがAI、されどAI。」のヒーロータイトル
3. ゲーム説明
4. 人類対AIのスコアモチーフ
5. 「ルームを作る」
6. 「ルームに参加」
7. 3ステップの遊び方

### 表現

- 黒背景
- 人類を黄色、AIをシアンで強調
- 装飾は円形の細線と斜めの境界線のみ
- ファーストビューでゲーム内容と主要操作が分かること

## 8. ゲーム画面

| 画面 | 主要表示 | 主要操作 |
|---|---|---|
| ルーム入力 | プレイヤー名、ルームコード | 作成または参加 |
| ロビー | 参加者、ホスト、準備、端末対応 | 準備OK、ゲーム開始 |
| ラウンド開始 | ラウンド番号、挑戦者 | お題を見る |
| 回答 | タイマー、お題、回答欄、文字数 | 回答確定 |
| 投票 | 匿名の回答A・B、投票者 | 回答カードを選択 |
| 公開 | 正体、票数、勝者 | 結果または挽回へ |
| 挽回 | 残り時間、回数、進捗 | 連打またはスマホ振り |
| ラウンド結果 | 得点、次の挑戦者 | 次ラウンドへ |
| 最終結果 | 最終得点、最優秀回答、履歴 | 再戦またはトップ |

## 9. 挽回チャレンジ

### 超連打

- 円形ボタン：最大260px、画面幅の68%
- 人類色の背景、5pxの黒い境界線
- `pointerdown`で加算
- 主ポインター以外は無視
- 押下時は8px沈み込む
- 35回到達時に即成功

### スマホ振り

- AI色の大きな操作面
- 端末モーション許可後のみ選択可能
- 振動中は小さな回転アニメーション
- 非対応または拒否時は連打へ切り替える

## 10. レスポンシブ

### 620px以上

- アプリを中央配置
- 外側へ24pxの余白
- アプリ外枠に角丸と境界線

### 360px以下

- コンテンツ横余白を18pxから14pxへ縮小
- 得点表示の最小幅を172pxから150pxへ縮小
- 全幅要素の負の余白も14pxへ合わせる

## 11. アクセシビリティ

- 操作要素は`button`、`input`、`textarea`を使用
- キーボードフォーカスは3pxのシアン系アウトライン
- 色だけで勝者・状態を伝えず、文字ラベルを併記
- タイマーと得点には`aria-label`を付与
- `prefers-reduced-motion`でアニメーションを停止
- 入力エラーは`role="alert"`で通知
- タップ対象は最低44px以上

## 12. アニメーション

- 通常のトランジション：80～160ms
- 点滅：AI生成中のドットのみ
- スマホ振り：600msの小さな回転
- 常時大きく動く背景演出は使用しない
- reduced-motion環境では実質0msへ変更

## 13. 実装上の注意

- プレイヤー回答はReactのテキストとして表示し、HTMLとして挿入しない
- APIキーや秘密情報をUIコードへ置かない
- 新しい色を追加する場合は`:root`のトークンへ定義する
- コンポーネント内へ直接カラーコードを増やさない
- スマートフォン幅320pxで横スクロールが発生しないことを確認する
- 実機ではiOSとAndroidのモーション許可動作を個別に確認する
